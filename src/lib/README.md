# `src/lib` layout

Code is split by **where it runs**, then by **domain**. The same domain folder names appear in every
layer, so "the review code" is always `review/`, `components/review/` and `server/review/`.

| Layer | Holds | Must not |
| --- | --- | --- |
| `<domain>/` | Types, rules and pure functions shared by server and browser. | Touch the DB, `$env`, the DOM, storage or Svelte context. |
| `components/<domain>/` | Svelte components, plus helpers only that UI uses (`*.svelte.ts` state, motion, sessionStorage snapshots). | Be imported from `server/`. |
| `server/<domain>/` | DB access, LLM calls, workflows. SvelteKit refuses to bundle it for the browser. | — |
| `client/` | Browser infrastructure any page may use (form attention, page transitions, scroll lock, timezone sync). | Hold single-domain helpers; those live with their components. |

A file with the same name in `<domain>/` and `server/<domain>/` (for example `review/manage.ts` and
`server/review/manage.ts`) is the shared contract and its server implementation.

## Domains

| Domain | Covers |
| --- | --- |
| `task` | Task content, lineups (daily/weekly distribution), which attempt a task URL shows. |
| `quest-hall` | The home book: menu model, navigation, preparation pages. |
| `practice` | Chat quests: sessions, the simulated platforms (`components/practice/ui/<variant>/`), hints, agent replies, the evaluation page, the translation help modal. |
| `translation` | Translation quests: drafts, evaluation (Generation 1 corrections, Generation 2 practice), second draft. |
| `review` | Notes, FSRS review, post-task transfer, note management (`/review`, `/review/manage`). |
| `streak` | Streak rules, history and presentation. |
| `auth`, `account`, `admin` | Sign-in; profile, avatar and trial quota; the task editor. |

Cross-cutting folders: `time/` (local days, display clock, browser timezone), `text/` (markdown,
`<mark>` parsing), `app/` (document language, `depends()` keys), `schemas/` (Zod form and JSON
schemas), `components/common/` (shared primitives), `components/shell/` (navigation and chrome),
`components/ui/` (generated by shadcn-svelte; do not hand-edit), `server/db/` and `server/llm.ts`.

"Practice" also names Generation 2 of translation evaluation (`server/translation/practice.ts`,
`PracticeCapsule.svelte`); inside `translation/` it always means that stage.

## Where a new file goes

1. Pick the layer by where the code runs, then the domain by what it is about.
2. Root of `lib/` holds only folders and three entry points: `constants.ts` (the single source for
   enums and labels), `i18n/` (`t()`), and `utils.ts` (`cn()`, fixed by `components.json`). Root of
   `components/` holds only folders.
3. Name files for what they do; the folder already says the domain (`server/translation/workflow.ts`,
   not `server/translation-workflow.ts`). No new `utils`/`helpers` buckets outside a single feature
   folder.
4. A domain with one file in a layer may be a single file named after it (`server/streak.ts`); make it
   a folder when a second file arrives.
5. Code used by exactly one route lives in that route's folder, not here.
6. Kebab-case for folders and `.ts` files, PascalCase for components, `*.svelte.ts` for rune modules.

Tests mirror this tree: `test/lib/<same path>.test.ts`. A second test file for one module is
`<module>.<aspect>.test.ts`; a contract test across a folder's modules is named for the contract
(`server/translation/evaluation/protocol.test.ts`).
